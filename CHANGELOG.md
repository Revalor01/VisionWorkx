# Changelog

Notable changes to VisionWorkx, newest first.

## Unreleased

- New Needs Analyzer **Website check** tab at `/admin/needs-analyzer/website` (operator only, hidden in Client mode): enter a business's site and it reads the home page plus up to 5 same-site pages (contact, booking, pricing, services, about) and reports the platform, what the site can and can't do (contact form, online booking, pricing/quote, reviews, chat, email signup, analytics, tap-to-call, social links), problems ranked high/medium/low, and which catalog modules fit. Recent checks are listed on the same screen.
- Website check → **Start assessment from this** creates a new assessment with answers filled in from the site (website, platform, lead sources, booking, quotes, email list, current tools, Website observations); **Apply to assessment** fills only answers that are still empty, so nothing the operator entered is overwritten. The questionnaire's first section and Internal notes show the latest check with *Check website* / *View check* links.
- Proposals can show a "What we found on <site>" section: only the website-check problems the operator ticks appear, on both the Proposal tab and the client link; nothing internal (scores, page text, AI review) is shown.
- Optional Google PageSpeed (mobile) scores in the website check, which add slow-on-phones / search / accessibility problems. Needs env var `GOOGLE_PAGESPEED_API_KEY` in Vercel; leave it unset to skip PageSpeed.
- Optional **AI review** of a checked site, run only when the operator clicks it: Claude Haiku 4.5 summarises the business, message clarity, calls to action, weak spots and talking points from the saved page text (about 1 cent, logged to `ai_usage_log` as `needs_analyzer_site_review`; uses `ANTHROPIC_API_KEY`).
- Needs migration `20240101000095_vw_na_site_checks.sql` (table `vw_na_site_checks`, main project, RLS on with no policies; each check can be linked to one assessment).
- Website check safety: the fetcher only follows http(s) on ports 80/443, refuses addresses with credentials, and checks every hostname, including each redirect hop, resolves only to public addresses (private, loopback, link-local, cloud metadata such as `169.254.169.254` and non-global IPv6 are refused); pages are capped at 2 MB and 8 seconds, at most 5 redirects.
- QA: `needs-analyzer.qa.ts` now also checks the website check screen and its APIs refuse without the operator; new unit tests `lib/needsAnalyzer/siteDetect.test.ts` and `siteFetch.test.ts`; four new manual checks in `qa/products/visionworkx/manual.json` (assessment end to end, website check, ticked problems on the proposal, AI review).
- New Needs Analyzer online at `/admin/needs-analyzer` (operator only, in the admin nav under Operations): the offline laptop sales tool's questionnaire, build plan, proposal, internal notes, ecosystem and catalog & pricing screens, with a Client mode that hides internal views. Needs migrations `20240101000093_vw_needs_analyzer.sql` and `20240101000094_vw_na_synced_at.sql` (tables `vw_na_assessments`, `vw_na_settings`, main project, RLS on with no policies).
- Client proposal links at `/proposal/<token>`: public, `noindex`, show only the proposal, and stop working when the link is turned off, regenerated or the assessment is deleted.
- Laptop sync: `scripts/needs-analyzer-sync.mjs` posts the offline app's assessments (and, with `--settings`, catalog and ecosystem) to `/api/needs-analyzer/sync`; never overwrites online edits. Needs env var `NEEDS_ANALYZER_SYNC_SECRET` in Vercel and on the laptop. `--url` must be https (or localhost).
- Needs Analyzer hardening: request bodies are refused on `content-length` before being read (512 KB operator saves, 8 MB sync), and logos render only from https addresses with `referrerPolicy="no-referrer"`.
- New QA tests in `qa/products/visionworkx/needs-analyzer.qa.ts` (admin needs the operator, sync needs the secret, unknown proposal links 404). Details: `docs/needs-analyzer.md`.
- Security: closed open redirects via `?next=` on `/login` and `/signup` (e.g. `/login?next=https://evil.example` no longer sends a signed-in user off-site) and a `/\host` gap in the admin SSO consume route (`app/api/admin/sso/consume`); only same-origin paths are followed now, otherwise the user lands on `/dashboard` (or `/admin` for SSO). Workspace login (`/workspace/login`) and its magic-link callback (`/workspace/auth/callback`) now get the same protections and must also stay inside `/workspace` (e.g. `/workspace/../admin` or `/workspaces-x` now land on `/workspace`).
- For developers: any user-supplied redirect target must go through `safeNextPath(value, fallback)` from `lib/safeRedirect.ts`, which returns a same-origin path or the fallback (it rejects absolute and protocol-relative URLs, backslashes, control characters, inputs over 2048 chars, anything that parses to another origin, and paths that collapse to `//` via dot segments). For redirects that must stay within one area, use `safeNextPathWithin(value, area)` (e.g. `area = "/workspace"`): same checks, and the resolved path must be the area itself or under it, otherwise it returns the area.
- Linting works again: ESLint moved to a v9 flat config (`eslint.config.mjs`, replacing `.eslintrc.json`) because Next 16 removed `next lint`; `npm run lint` now runs `eslint .`.
- Lint skips code that isn't the app's own Next.js source: `templates/**`, `supabase/functions/**`, `public/embed.js` and `lib/apps/baseTemplate.generated.ts`.
- The newer React Compiler-era react-hooks rules (`set-state-in-effect`, `purity`, `immutability`, `use-memo`, `preserve-manual-memoization`) are errors again: all 35 warnings they raised (plus one `exhaustive-deps`) were fixed across admin screens, workspace/billing/generate pages and customer-facing components, and the temporary warn-downgrade was removed, so a new violation fails lint and CI.
- New `lib/hooks.ts` for developers: `useOnChange(value, fn)` adjusts state during render when a value changes (use it instead of `setState` inside a `useEffect`), and `useNow(intervalMs)` gives a ticking clock (use it instead of `Date.now()` during render in client components).
- Server components that read the clock per request keep `Date.now()` with a commented `eslint-disable` for `react-hooks/purity`.
- Behaviour notes from those fixes: the admin Payments tab still retries on re-open until one load succeeds; the admin Marketing and Mobile dashboards, the social Performance tab and the booking widget now ignore stale fetch responses.
- CI (`.github/workflows/ci.yml`) now runs a Lint step after Typecheck, so lint errors fail the check.
- Social content (`/admin/social`) now follows the Revalor Business framework from products.revalorllc.com: VisionWorkx is described as website modules plus automation (Starter $59 / Growth $129 / Pro $299, 14-day trial), not an AI app builder.
- Content calendar generation adds each brand's current product facts (`lib/social/productKnowledge.ts`) to the prompt, and those facts override older positioning in brand voice notes.
- The "Revalor LLC" social brand now gets product facts for the three Revalor Business products (VisionWorkx, Proactive, Revalor Consulting); the earlier mapping keyed on a "Revalor Business" brand name that doesn't exist.
- LinkedIn posts can now be written for "Revalor Consulting" as a product (needs migration `20240101000091_linkedin_consulting_product.sql`).
- The weekly recap prompt now describes Revalor's six products across three lines (Business, Kids, Wellness), and its stats still cover only VisionWorkx, Chorebit, FeelFlow and MindBit.
